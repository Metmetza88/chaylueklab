# รับเงิน PromptPay แบบเจ้าของตรวจยอด

ระบบรองรับเริ่มต้นด้วยเจ้าของตรวจยอดเข้าธนาคารและอนุมัติใน Admin แล้วเปิดสิทธิ์ดาวน์โหลดอัตโนมัติ ไม่จำเป็นต้องมี API ตรวจสลิปเพื่อใช้ workflow นี้ ส่วนการตรวจอัตโนมัติผ่าน provider ต้องมีบัญชี/API ที่ได้รับอนุญาตและ adapter ของผู้ให้บริการจริงก่อน

## สถานะ Release Candidate

ยังไม่รับเงินจริง ค่าเริ่มต้น `PAYMENT_MODE=disabled`, `PAYMENT_WEBHOOK_ENABLED=false`, `LIVE_PAYMENTS_APPROVED=false` และ DB live gateปิดอยู่ Sandboxใช้ข้อมูลสมมติ/ไม่ออก QR รับเงินจริง CI ผ่าน uploadสลิปจริงบนprivate Storage, duplicate rejection, wrong amount, manual Sandbox confirmation, grant และ download แล้วตาม TEST-REPORT.md ไม่ใช่หลักฐานว่ารายการเข้าธนาคารจริงหรือ provider APIผ่านแล้ว

## วิธีเจ้าของใช้งานเมื่อผ่านการตรวจรับและอนุมัติเงินจริงแล้ว

1. ตั้ง merchant PromptPay/ข้อมูลผู้รับที่ถูกต้องใน Secret Settings ของ Project ที่ยืนยันแล้ว ตรวจชื่อผู้รับและยอดที่แอปธนาคารแสดงก่อนใช้งานจริง ไม่ส่งข้อมูลลับผ่านแชต
2. ลูกค้าสร้าง orderจากราคาในDB และอัปโหลดภาพ PNG/JPEG ระบบเก็บprivate/re-encode/ตรวจhashซ้ำ อัปโหลดแล้วสถานะยังรอตรวจ ไม่มีgrantทันที
3. เจ้าของเข้าสู่ `/admin` ด้วยบัญชีของตน เปิดหลักฐานผ่านลิงก์อายุ60วินาที แล้วเปิดแอปธนาคารตรวจยอดเข้าจริง ผู้รับ วันที่ และเลขอ้างอิง ห้ามยืนยันจากภาพเพียงอย่างเดียว
4. กรอกเลขอ้างอิงและยอดหน่วยสตางค์ (3,500บาท =350000) แล้วรับรองว่าตรวจธนาคารแล้ว ระบบปฏิเสธยอดไม่ตรง/เลขอ้างอิงซ้ำ และเก็บค่าฟอร์มไว้ให้แก้เมื่อvalidationไม่ผ่าน
5. เมื่ออนุมัติสำเร็จ payment/grant/audit/outboxถูกบันทึกด้วยtransaction ลูกค้าเข้าสู่หน้าดาวน์โหลดแล้วได้รับsigned URLอายุ60วินาที ไม่ต้องส่งไฟล์ด้วยตนเอง
6. การคืนเงินในAdminคือบันทึกหลังคืนเงินจริงภายนอกแล้ว ไม่ได้โอนเงินแทนธนาคาร ระบบถอนgrantหลังบันทึก การส่งLINE/emailต้องตั้งreceiver/schedulerจริงก่อน ไม่อ้างว่าส่งสำเร็จเมื่อไม่มีการตอบรับ

## การตรวจรับก่อนเปิดเงินจริง

ต้องมี Preview/Hosted DB ที่ได้รับอนุญาต ตรวจสิทธิ์/Auth/Storage/CDN/SMTP/backupและอุปกรณ์จริง ตั้งmerchantจริง ตรวจSandboxworkflowกับเจ้าของ แล้วอนุมัติการเปิดเงินจริงแยกตาม DEPLOY-TH.md CI/Deployรุ่นRCตั้งใจบังคับpayment disabled เพื่อไม่เปิดเงินจริงจากการMergeหรือPush ต้องปรับ release configurationหลังการตรวจรับและอนุมัติที่ระบุชัดก่อนใช้live

MET School Pro/Admissionที่ติดตั้งด้วย `APP_VARIANT=school` ปิดระบบรับเงินร้านค้าเสมอ การตรวจรับSourceโปรแกรมโรงเรียนแยกจากการอนุมัติระบบรับเงินจริงของร้าน ไม่อ้างว่าต้องซื้อAPIตรวจสลิปเพื่อเปิดเว็บไซต์หรือระบบรับสมัครโรงเรียน
