## วิธีทดลองในเครื่องพัฒนา

จาก root repository ใช้ Node.js 24+:

```sh
node --test tests/*.test.mjs
node scripts/build-public-site.mjs
python -m http.server 8765 --bind 0.0.0.0 --directory _site
```

เปิด `http://localhost:8765/satuek-connect/` อย่าใช้ web root นี้เปิดตรงไปยัง source repository เพราะมี SQL และไฟล์ฝั่งเซิร์ฟเวอร์

ทดสอบ UI และสร้างภาพหน้าจอ:

```sh
cd tests/satuek-connect
npm ci --ignore-scripts
npx playwright install --with-deps chromium webkit
npm test
```

คำสั่งติดตั้ง browser dependencies ต้องใช้สิทธิ์ระบบปฏิบัติการ หรือใช้เครื่อง/คอนเทนเนอร์ที่มีไลบรารีครบ ใน workspace งานนี้ใช้ไลบรารีแยกใน `/tmp` และ browser cache เพราะไม่มี root; ข้ามเพียงการตรวจ package ของ host ที่ไม่รู้จักไลบรารีแยก แต่รัน WebKit/Chromium และทดสอบจริง ไม่ได้ข้าม assertions

สร้าง Tailwind ใหม่เมื่อแก้ utility class: `npm run css` ในโฟลเดอร์ทดสอบ แล้ว build เว็บใหม่ CSS อื่นอยู่ในหน้า HTML เดียว

ใช้ `SATUEK_BASE_URL=https://<preview-host>/satuek-connect/ npm test` เพื่อตรวจ Preview ที่เข้าถึงได้ หาก Preview มี Vercel Authentication ให้เจ้าของล็อกอิน/ตั้งสิทธิ์ Preview ตามนโยบายเดิมก่อน ไม่แก้ปิดการป้องกัน Production

## วิธีใช้งานบน iPhone

1. เมื่อมี Preview URL ที่ตรวจสอบแล้ว เปิดลิงก์ `/satuek-connect/` ผ่าน Safari ขณะนี้อย่าใช้ URL เก่าของเว็บหลักแทน Preview ของ branch นี้
2. ใช้เมนูด้านล่าง 4 เมนู หรือค้นหาจากหน้าหลัก เช่น “ข้าว” “ช่างไฟฟ้า” “ท่าม่วง”
3. ที่ตลาด กด “ลงขายสินค้า” เลือกหมวดและตำบล กรอกชื่อ ราคา หน่วย ชื่อร้าน รายละเอียด แล้วยืนยันเงื่อนไขและบันทึก
4. เปิดรายละเอียดประกาศของคุณแล้วกด “แก้ไขประกาศ” เมนูบัญชีมุมบนขวารวมประกาศที่เป็นของเครื่องนี้
5. รีเฟรชหน้า ข้อมูลยังอยู่ในเบราว์เซอร์เดียวกัน หากเปิดใน LINE หรือเครื่องอื่นจะเป็นคนละพื้นที่จัดเก็บ
6. ที่ “ช่วยเหลือ” การแจ้งเรื่องเป็นเพียงการทดลอง ไม่ได้ส่งหาหน่วยงาน หากมีอันตรายต่อชีวิตโทร 1669 โดยตรง ห้ามโทรเพื่อทดสอบ
7. ใช้ “ความเป็นส่วนตัว” → “ล้างข้อมูลเดโม” เมื่อต้องการลบข้อมูลของ Satuek Connect โดยไม่ล้างข้อมูลเว็บเดิม

ยังไม่ได้ทดสอบบน iPhone/Android เครื่องจริง รวมทั้งการโทรจริง, คีย์บอร์ด Safari, Add to Home Screen, พื้นที่ Safe Area จริง และ LINE in-app browser ผล WebKit จำลองไม่ทดแทนการตรวจอุปกรณ์จริง

## Supabase และแบบข้อมูล

ตรวจสอบ read-only แล้วเมื่อ 21 พฤศจิกายน 2569:

- บัญชี Primary: `Metmetza88's Project` ref `yobymeygbfiwlngmwjcn` มี endpoint ที่ Repository เดิมใช้งานอยู่
- อีกบัญชี: `CHAYLUEKLAB Reminder Backend` ref `bxaplhrunxiadjsdobyl` ไม่ย้ายงานไปโปรเจกต์นี้
- โปรเจกต์แรก ACTIVE_HEALTHY มีตาราง billing, video, newsroom, stock และ awareness เดิมเปิด RLS แต่ไม่มี schema/tables สำหรับ Satuek Connect
- ไม่สร้าง Supabase project ใหม่ ไม่รัน SQL หรือแก้ Auth/Data API บนระบบจริง ไม่อ่านข้อมูลประชาชนหรือ Secret

`schema.sql` คือ **แบบ SQL ที่ยังไม่ apply บน Supabase จริง** แยก `satuek_connect` schema มี `users`, `shops`, `products`, `services`, `reviews`, `help_requests`, `reports` ครบ พร้อม FK, constraints, indexes, RLS, column grants, ตรวจ ownership, reset การเผยแพร่เมื่อแก้เนื้อหา และ trigger จำกัดโพสต์

ทดสอบ DDL และ RLS บน PostgreSQL 17 ใน Docker แยกด้วย `tests/satuek-connect/database.sql` ใช้ Auth helper จำลองและ rollback ข้อมูลทดสอบ ผลนี้ยังไม่ยืนยันว่า Auth/REST/Storage ใช้ได้บน Supabase Production

ก่อนเชื่อมข้อมูลจริงต้องเลือกวิธี Supabase Auth หรือ LINE ที่ตรวจ token ฝั่งเซิร์ฟเวอร์, กำหนดเจ้าของ/ผู้ตรวจสอบ, สร้าง migration ผ่าน Supabase CLI ตามขั้นตอน, ทดสอบ staging, expose เฉพาะ schema ที่จำเป็น และเชื่อม frontend กับข้อมูลจริง ห้ามใช้รหัส LINE user ID ที่ client ส่งมาเพื่อมอบสิทธิ์ ห้ามใช้ user_metadata เพื่อให้สิทธิ์ผู้ดูแล

สิทธิ์ตรวจสอบอาศัย `app_metadata.satuek_role` ที่ server ออกเท่านั้น JWT ต้อง refresh หลังเปลี่ยนบทบาท การยืนยันตัวตน/ติดต่อ/รีวิว/การชำระเงินต้องมี endpoint ฝั่งเซิร์ฟเวอร์ที่ตรวจผู้ดูแลและบันทึกหลักฐาน audit ก่อนใช้ service role; endpoint เหล่านี้ยังไม่ติดตั้ง ไม่ใส่ service role หรือ Channel Secret ใน frontend

## LINE LIFF

`satuek-connect/config.js` เว้น `liffId` ว่างโดยตั้งใจ ไม่ยืม ID/Endpoint ของ CHAYLUEKLAB ซึ่งอาจเปลี่ยน callback ของเว็บเดิม

เมื่อเจ้าของมี LIFF สำหรับแอปนี้ ให้กำหนด LIFF ID สาธารณะและ HTTPS Endpoint ให้ตรงกัน โค้ดจะโหลด SDK เมื่อกดเข้าสู่ระบบ, เรียก `liff.init`, ตรวจ `isInClient/isLoggedIn`, และเตรียม `liff.login` พร้อมแจ้งข้อผิดพลาด ไม่มีการอ่านหรือเก็บ access token ในเดโม และยังไม่แปลง LINE login เป็นสิทธิ์ในฐานข้อมูล
